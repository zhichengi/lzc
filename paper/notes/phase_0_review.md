## 一、这个阶段学到的最重要的三件事

### 1. 复现的差距几乎全部来自「论文写的 vs 代码做的」，不是环境

五条线全部定位到论文—代码缺口，没有一条是纯粹的"环境装错"或"随机波动"：

| 线 | 定位到的失配 |
|----|--------------|
| ScaDyG | checkpoint 只存预测层；AP 选模 vs MRR 主指标；排名协议（每源最佳正边 + 全节点负采样） |
| GCTD | 默认 `lr_rec` + 0.05 阈值必得完全图；合成特征用 class+split 原型；Table 2 超参未公开 |
| SGPC | `Best Test` 是 test 选模；论文写"每类 20 点"但代码用 PyG 自带 split；无 seed |
| IGNN | V100 vs 3090 硬件差异；`graph_datasets` 丢 NPZ public mask（协议不纯） |
| GBN | `layer_wise` 不在 argparse；`γ0,β0` 常数未公开；`βi=0` 代码映射不完整 |

**结论**：环境只要跑得通就不再是主要矛盾；真正的工作量在"读代码、对照论文文字、设计能区分假设的对照实验"。

### 2. 分层判定（L1/L2/L3）+ 时间盒，让复现可以"体面地停"

`REPRO_ROADMAP.md` 第 5 节的三级标准是本阶段最有用的工具。它把"复现成功/失败"这种二元判断，拆成可以分别回答的三个问题，于是**在 L2 停下并冻结成为合法结局**——只要写清 L3 未达的原因。

反例对照：GCTD 在 Cora 上做了约 15 轮实验仍未到 L3，超出时间盒；引入停止规则后，GBN 与 ScaDyG 都按规则及时冻结，没有再扫参。

**结论**：三级标准 + 时间盒的组合，比"再试一次"更能保护时间预算。最有价值的产出往往是第 7 步定位的失配原因，而不是把数字调上去。

### 3. 可追溯性靠四件套，且必须"可被别人重放"

每条冻结线都做到了同样的四件事，缺一件就无法自证：

1. **固定提交 SHA**（官方克隆回退到确定版本，工作区干净）
2. **补丁文件**（对官方代码的改动，`git apply --check` 可验证）
3. **独立运行日志**（每次运行一个文件，含 commit / 环境 / GPU / 完整命令，不覆盖）
4. **结构化 CSV**（可被解析、跨线对比）

ScaDyG 这条线还额外暴露了一个真实风险：早期补丁（`scadyg-paper-protocol.patch`）**没有覆盖后续工作树**，导致一度无法追溯。补救方式是生成覆盖完整源码的 `scadyg-current.patch`，并在**干净 worktree 上从官方提交重新应用、逐字节比对、通过编译**才算验证完成。

**结论**："写了补丁"不等于"补丁能重建当前状态"；验证要用干净环境重放，不能只对照工作树。

## 四、下一阶段（P1）的安排与风险

P1 计划：29 SGPC 收尾 → 09 GBN → 10 Stable-ChebNet。SGPC 与 GBN 均已完成，**实际剩下的只有 10 Stable-ChebNet**。

- **主要阻塞**：Dropbox 上的 Peptides-func / struct 数据不通。需先解决数据获取，否则 P1 无法继续。
- **备选路径**：若数据短期内仍不通，可先做 01 Equivariance（同属 M6，需先装 gcc 解决 Triton 编译），避免 GPU 与注意力空转。
- **同步学习**：M1 剩余项（ChebNet / BernNet 滤波曲线、PAC-Bayes 与谱）与 M5 的 LRGB 部分应与 Stable-ChebNet 一起推进，而不是等复现做完再补。
- **纪律**：仍不开并行；每篇按标准十一 步走，改官方代码一律"默认关闭开关 + 补丁 + 干净环境验证"。
